# 抖音作品数据获取方案（调研）

本文只做调研与选型，**没有对应代码改动**。目标：用户在杭客松提交一条抖音作品分享链接后，
平台能显示这条作品的**文案**与**点赞 / 评论 / 转发数**。

## 结论（先看这段）

1. **推荐**：在你自己那台阿里云轻量服务器上自建
   [Evil0ctal/Douyin_TikTok_Download_API](https://github.com/Evil0ctal/Douyin_TikTok_Download_API)，
   **只监听内网或非标端口 + 共享密钥**，由 hangkathon.net 的服务端路由调用它，浏览器永远不直接碰它。
2. **并行保留手动填写 + 截图佐证**：零后端、零密钥、零法律风险，而且截图比手填难伪造，
   正好对上平台「评审不能被流量逻辑带偏」的顾虑。建议作为默认路径，自动抓取作为加速项。
3. **不要**采用 RandallAnjie/Douyin-API（未声明许可证 = 无权使用）、LightJUNction/douyin（AGPL-3.0 + 形态是 CLI）、
   mafqla/douyin-api（GPL-3.0，且它自己的 issue 就是 cookie 失效）。
4. **抖音开放平台官方接口不满足需求**：它只能读「授权了你应用的账号自己」的作品，读不了任意用户贴的任意链接。
5. **必须接受的前提**：自建这类方案本质上是在**绕过抖音的反爬签名**，违反抖音用户协议；
   国内已有 破坏计算机信息系统 / 不正当竞争 方向的判例先例。所以它只能作为**私有加速项**，
   不能做成公开 API，且要限流、缓存、只存公开指标、留投诉下架通道。

## 平台现状（和这件事相关的部分）

- 提交入口**已经有了**：`app/activities/[slug]/activity-detail.tsx` 里，活动接受「演示视频」时出现
  「作品提交」，输入框占位文案就是「粘贴抖音视频分享链接」。
- 校验**已经有了**：`lib/submission.ts` 的 `isValidDouyinUrl`（只认 v.douyin.com / www.douyin.com/video/数字 /
  iesdouyin.com/share/video/数字），配套测试 `scripts/douyin-url.test.mjs`。
- 存储**看部署**：没有数据库的部署（Vercel）写 localStorage `hangkathon.submissions.v1`，每个活动上限 20 条；
  自托管那份（2026-09-24 起）走服务端 `submissions` 表，按登录账号归属，只有本人看得到自己的提交。
  两种情况都**没有** 文案/点赞/评论/转发字段。
- **后端已经就位（自托管那份）**：Postgres + `/api/activities/[slug]/submissions` 等路由，
  所以抓取服务有地方落：新增一个服务端路由调抓取服务、把结果写进 `submissions` 表即可；
  Vercel 那份没有数据库，只能先走手动填写。
- **文档口径矛盾，需要统一**：`README.md` 写着「活动全程在杭客松平台内进行……创建流程里没有任何要求填写外部网址的字段」，
  但详情页已经有抖音链接提交表单了。这条要么改文档、要么改产品，不能两存。

## 推荐架构

```
浏览器（hangkathon.net）
   │  POST /api/douyin/resolve { url }        ← 分享链接，不携带任何密钥
   ▼
Vercel 路由（服务端，持有 DOUYIN_API_BASE + DOUYIN_API_SECRET 环境变量）
   │  校验域名与链接形状 → 限流 → 查缓存 → 出网调用
   ▼
你的阿里云轻量服务器（Evil0ctal 容器，只监听内网/非标端口 + 共享密钥）
   │  解析分享短链 → 取作品详情
   ▼
返回 { caption, digg, comment, share, collect, fetchedAt } → 写回提交记录
```

为什么这样切：

- **密钥不出服务端**。任何 API Key / Cookie 放到浏览器里都等于泄露（TikHub 的 Key 是计费凭证，抖音 Cookie 是账号）。
- **抓取服务与公开站点分离**。抖音反爬会封 IP，封的应该是一台你可以重开的机器，不是 hangkathon.net。
- **大陆 IP 成功率更好**。你那台阿里云机器在国内，比 Vercel 的海外出口更容易拿到数据。
- **缓存按 `aweme_id`**。作品数据变化慢，缓存能同时省调用量和降低被风控的概率。

### 成本

- 自建：只有服务器固定成本（你已有），边际成本 ≈ 0。
- 备选 TikHub：每次 0.001–0.01 美元，500 份提交不到 1 美元；注册送约 50 次免费调用，
  足够先跑通全流程再决定要不要充值。

## 你那台阿里云轻量服务器的具体注意事项

1. **不要对外提供网页服务**。中国大陆地域的轻量服务器，对公网提供 80/443 的网页服务需要 ICP 备案；
   只被自有后端按 IP + 非标端口调用则不触发备案要求。所以建议：**不绑域名、不开 80/443、只放一个非标端口**，
   并且在安全组里把来源限制成 Vercel 的出网地址段（或至少加共享密钥 + 限流）。
2. **资源要留够**。轻量机型常见 2C2G/2C4G，Evil0ctal 带 Postgres 归档会偏紧；
   如果只是给杭客松用，建议**先不归档**（或换 SQLite），把内存留给抓取本身。
3. **阿里云会对滥用投诉做处置**。抓取流量异常、被投诉，可能收到工单甚至停机。
   这也是「限流 + 缓存 + 不公开」的现实理由，不只是法律理由。
4. **Cookie 会失效，签名会轮换**。这是常态化运维，不是一次性投入：
   需要定期更新 Cookie，并在接口报 403 时能及时发现（建议加一个最简单的健康检查）。
5. **留一条下架通道**。如果被要求删除某条作品的数据，要能一条命令删掉。

## 代码接入点（真正动手时改这些地方）

1. `lib/submission.ts`：`SubmissionRecord` 扩成
   `{ url, submittedAt, caption?, digg?, comment?, share?, collect?, fetchedAt? }`，
   `normalize` 风格地容错（老记录没有这些字段也要能读）。
2. 新增服务端路由 `app/api/douyin/resolve/route.ts`：校验 `isValidDouyinUrl` → 调自建服务 → 返回精简后的字段。
   密钥只从环境变量读，且**只在服务端**。
3. 详情页「作品提交」列表：每条行内显示文案摘要 + 点赞/评论/转发，并提供「刷新数据」按钮
   （抖音数据会变，不要自动轮询，省调用也省风控）。
4. 保留手动填写作为兜底：抓取失败时允许用户自己填数字并附截图。
5. 统一 `README.md` 的口径（见上文「文档口径矛盾」）。
